# Tax Steps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Tax Steps — scan → AI extract → review → save → realtime sync → dashboard → report → export — as a Next.js web app and an Expo iOS/Android app on one Supabase backend.

**Architecture:** npm-workspaces monorepo. `packages/core` (pure, Deno-compatible TS: schemas, registries, regions, dates, money, filters, CSV, draft logic) is shared by both apps *and* the Edge Functions. `packages/data` (supabase-js API calls + TanStack Query hooks + realtime) is shared by both apps. All secrets and heavy work (OpenAI extraction, CSV/XLSX/PDF, Google Sheets, account deletion) live in Supabase Edge Functions; clients hold only the publishable key and rely on RLS. (Refinement over spec §3: `packages/data` added so web and mobile don't duplicate data access.)

**Tech Stack:** Next.js 16.3 · Expo SDK 57 (expo-router 57, react-native 0.86.3) · React 19.2.3 · TypeScript ~6.0.3 · zod 4 · @supabase/supabase-js 2.117 · @supabase/ssr 0.12 · @tanstack/react-query 5 · Vitest 5 · Deno 2.9 (functions) · SheetJS 0.20.3 (CDN build) · pdf-lib 1.17.1 + @pdf-lib/fontkit · lucide-react / lucide-react-native · Playwright (one journey test).

**Spec:** `docs/superpowers/specs/2026-10-05-tax-steps-design.md` (read it; this plan argues from it).

## Global Constraints

- React and react-dom pinned to exactly `19.2.3` in every workspace (Expo SDK 57 requirement; one React copy in the monorepo). TypeScript `~6.0.3` everywhere.
- `packages/core` must not import Node or browser APIs and must use explicit `.ts` relative import specifiers (`./money.ts`) so Deno can import it. Only dependency: `zod`.
- Receipt images/PDFs are never written to DB, Storage, disk (beyond the OS camera temp file, deleted immediately), logs or analytics. Functions never log request bodies or extracted values.
- AI output is never saved directly; only the user's explicit Save writes a `documents` row.
- Clients only ever see `SUPABASE_URL` + publishable (anon) key. OpenAI key, Google secret, token key, state secret, service-role key are Edge Function secrets only.
- All money arithmetic in integer cents; DB stores `numeric(14,2)`; totals are always grouped by currency (no FX).
- `transaction_date` is a calendar `date` (no tz). "Today/this month/this FY" is computed in the profile `timezone`. Default timezone fallback `Pacific/Auckland`.
- OpenAI: `POST https://api.openai.com/v1/responses`, `store: false`, `text.format = { type: "json_schema", name: "receipt_extraction", strict: true, schema }`, image as `{ type: "input_image", image_url: "data:<mime>;base64,<b64>", detail: "high" }`, PDF as `{ type: "input_file", filename, file_data: "data:application/pdf;base64,<b64>" }`, read `output_text`. Model from `AI_MODEL`, default `gpt-6.1-sol`.
- Design: Organic design system (`TaxSteps/_ds/organic-*/styles.css`), mockups `TaxSteps/Web App.dc.html` and `TaxSteps/Phone App.dc.html`, rebranded "TrackerRabbit" → "Tax Steps". Lucide icons, `strokeWidth={2.75}`. Pill buttons, large radii, Caprasimo headings, Figtree body.
- Exact copy (put in `core/src/copy.ts`, never retype elsewhere):
  - tagline: `Tax Steps helps you organise and prepare your expense records for tax time.`
  - disclaimer: `Tax Steps helps you organise and prepare your expense records for tax time. You are responsible for deciding whether an expense is deductible — please consult a qualified tax professional where appropriate.`
  - photoPrivacy: `Your photo is used only to extract the information. It is not stored after processing.`
  - privacyPanel: `Receipt photos are never stored. We extract the details, then discard the image — no copies in our database, storage or logs.`
  - providerNote: `Images are sent to our AI provider (OpenAI) for extraction with storage disabled; the provider may retain API inputs for up to 30 days for abuse monitoring.`
  - error copy exactly as spec §13.
- Rate limits: extract 30/hour and 300/day per user; export 60/hour; sheets 60/hour.
- Commit after every task (`git add` the task's files; message `feat(<area>): …`). Never commit `.env*` files except `.env.example`.

## Review Focus

1. **Non-Latin-1 text in PDF exports** (Māori macrons "Kōwhai Build", CJK "東京ストア", emoji) — export must succeed, unsupported glyphs replaced with `?`. Test owned by Task 8.
2. **Timezone day boundary** — at `2026-09-30T12:30:00Z` it is already 1 Oct in `Pacific/Auckland`; "this month" must be October there and September in `America/New_York`. Test owned by Task 2.
3. **Mixed currencies in one period** — NZD and AUD receipts in the same month must produce two totals, never one sum. Tests owned by Task 4 (shaping) and Task 6 (SQL).
4. **Double Save / offline retry** — saving the same draft twice (double-tap, retry after timeout, queue flushed twice) must leave exactly one row. Tests owned by Task 6 (`saveDocument` upsert) and Task 19 (queue).
5. **Locale-formatted user input** — `"$87.45"`, `"1,234.56"` (en-NZ), `"1.234,56"` (de-DE), `"05/10/2026"` (en-NZ = 5 Oct; en-US = 10 May) must parse correctly or produce a field error, never a silently wrong value. Tests owned by Tasks 1, 2, 3.
